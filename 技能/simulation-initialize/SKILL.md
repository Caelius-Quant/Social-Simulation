# 初始化

本 Skill 唯一规定从启动输入到第一次输出的跨主体顺序。人物与世界怎样建档由对象文件定义，接口与返回条件由协议定义；正常完成后由推进 Skill 承接后续输入。

## 一、入口

按 `AGENTS.md` 路由进入，确认已经读取：

- `协议/状态协议.md`、`协议/分权与交互协议.md`、`协议/文件管理协议.md`。
- `对象/角色智能体.md`、`对象/世界控制器.md`。
- `技能/simulation-advance/SKILL.md`：首次输出使用其第二节“首次输出”入口。

先按文件管理协议确认新建目标及运行编号。恢复旧运行交推进 Skill；已有不完整运行按恢复规则处理。以下候选内容按文件管理协议第六节的建档草案例外留在当次工作中，不提前建正式运行文件或展示未提交场景。

启动默认只需要用户性别与对象性别，缺哪项询问哪项。本次未提供的其他用户资料保持未知，不使用其他聊天、隐藏画像或账户资料补齐。用户偏好与期望关系不传给人物建档；明确提供的排除校验材料只供建档检查。

用户可以自愿提供课表、行程和其他客观限制，但不把完整生活档案变成启动要求。将这些资料交世界核对适用日期、现实条件和冲突；不据此给人物匹配兴趣或安排相遇。区分已确定安排与希望获得建议的空档，收到一周行程不等于获准立即推进一周。

保留启动输入中的明确行动、推进要求或行动建议请求，待建档保存后交统一推进入口处理。助手不参与人物或世界建档；首次输出确需辅助时，由推进 Skill 按需读取助手对象，不在此增加一套候选生成流程。

## 二、组织建档

### 1. 请求世界客观边界

向世界发起建档调用，范围为“客观边界”，传入合法启动信息。世界按对象第十二节返回初始客观内容及必要人物生成约束；本步不请求双方社会位置。

### 2. 请求独立人物

向角色发起建档调用，传入对象性别、必要环境约束和已明确提供的校验材料。角色按对象第十三节生成并检查人物，按交互协议分离私人内容与必要外部背景。

接收本主体检查结果。未通过时让角色局部修正受影响内容；运行器不代改人物，也不选择更讨喜的候选。

### 3. 请求社会位置与起点观察

人物独立成立后，只将必要外部背景交世界，发起“外部相容性与社会位置”建档调用。世界按对象方法核对并形成分主体起点信息草案。

将草案中的角色起点信息交角色作建档校准，保留需要后续处理的当前事项。正式建档保存后，这些已校准信息不再重复投递为新观察。客观冲突回到世界或受影响的建档步骤核查，不把完整私人内容交世界解决。

### 4. 取得建档确认

分别请求世界和角色确认各自内容。世界检查客观相容性；角色检查人物及其认识；运行器核对步骤二已先于步骤三完成，以及交接是否使用了正确接收方。

未通过时仅返回负责该内容的步骤并复核受影响的下游。必要资料缺失或权威无法解决的冲突，按根入口报告；合法人物缺少共同点不构成重建理由。

## 三、保存与首次推进

两个主体确认后，调用文件管理协议第六节保存程序，创建当前编号下的三份初始文件。起点背景及初始账本内容依状态协议处理，不在本 Skill 重定义。

保存完成后，将运行编号、起点、用户起点观察、已接纳安排与尚待处理的启动请求交推进 Skill 的“首次输出”入口；只交接该入口需要的授权材料。角色的最小调度信息由推进分支需要时查询，不为纯建议或起点展示提前唤起决策。人物的当前事项已经在本侧状态中，不另建初始化交接文件。

初始化期间若收到明确世界内行动或推进要求，建档后交同一个推进入口处理，不得据此反向定制人物。有建议请求而没有行动时，在起点提供候选并等待选择；没有这些请求就交还起点控制，不虚构用户输入或先跳时寻找交互。

复用推进 Skill 直至第一次输出完成。若已有合法建档但首次推进被阻塞，报告已保存的编号及具体阻塞；下次从该运行恢复，不再次建档。

## 四、边界与例外

只组织对象调用，不在此复制人物生成维度、世界补足方法、保存程序或停止条件。执行时使用其唯一权威正文。

候选比较与校验过程不成为人物经历。首次输出根据交互协议成立，呈现起点可知处境而不另加欢迎剧情或安排初次相遇；保存失败按文件管理协议处理。

## 五、执行形态示例

- 正常新建：世界边界 → 独立人物 → 社会位置与局部观察 → 分别确认 → 保存 → 首次推进及输出。
- 建档已保存，首次推进缺必要资料：报告当前编号和缺项；资料补足后用推进 Skill 恢复，不重复生成人物。
- 启动时附课表并请求“给今天下午几个安排建议”：世界核对课表 → 按原顺序完成独立建档并保存 → 推进 Skill 的辅助分支提供候选 → 在起点等待用户选择，不直接执行一周行程。
