# 初始化

本 Skill 唯一规定从启动输入到第一次输出的跨主体顺序。人物与世界怎样建档由对象文件定义，接口与返回条件由协议定义；正常完成后由推进 Skill 承接后续输入。

## 一、入口

按 `AGENTS.md` 路由进入，确认已经读取：

- `协议/状态协议.md`、`协议/分权与交互协议.md`、`协议/文件管理协议.md`。
- `对象/角色智能体.md`、`对象/世界控制器.md`。
- `技能/simulation-advance/SKILL.md`：首次输出使用其第二节“首次输出”入口。

先按文件管理协议确认新建目标及运行编号。恢复旧运行交推进 Skill；已有不完整运行按恢复规则处理。以下候选内容按文件管理协议第六节的建档草案例外留在当次工作中，不提前建正式运行文件或展示未提交场景。

启动默认收集用户性别、对象性别，以及用户的基本身份与所处阶段。学生询问专业和年级，在职者询问职业及工作阶段，其他身份按其实际情况说明即可。合并询问缺项，已提供的内容不重复问；不要求真实姓名、具体单位、完整课表或生活档案。

缺项时可问：“请补充你的性别、模拟对象的性别，以及你的基本身份，例如什么专业、几年级，或从事什么工作、处于什么阶段。”实际输出只保留尚缺的部分。用户明确不愿提供某项时保留未知，不重复索取，由世界判断能否在不依赖该信息的环境中启动；确有不可绕过的必要缺项才说明原因并暂停建档。

场景条件和事实文件均为可选输入，未提供场景不构成启动缺项。其他未提供的用户资料保持未知，不使用其他聊天、隐藏画像或账户资料补齐。用户偏好与期望关系不传给人物建档；明确提供的排除校验材料只供建档检查。

用户可以自愿提供课表、行程和其他客观限制，但不把完整生活档案变成启动要求。将这些资料交世界核对适用日期、现实条件和冲突；不据此给人物匹配兴趣或安排相遇。区分已确定安排与希望获得建议的空档，收到一周行程不等于获准立即推进一周。

保留启动输入中的明确行动、推进要求或行动建议请求，待建档保存后交统一推进入口处理。助手不参与人物或世界建档；首次输出确需辅助时，由推进 Skill 按需读取助手对象，不在此增加一套候选生成流程。

## 二、组织建档

### 1. 请求世界客观边界

本步完成场景确定与资料接入，再请求世界返回初始客观内容及必要人物生成约束。场景选择、补足和事实核对由世界按对象第十二节判断；运行器负责查找文件和传递材料。本步不请求双方社会位置。

先区分用户的输入：

| 启动输入 | 调用与资料处理 |
| --- | --- |
| 未给任何场景条件，也未指定文件 | 将已提供的基本身份交世界，请其创建相容的普通生活场景；随后按确定的场景范围检索可用资料。即使本地已有文件，也不由文件数量或排序替用户预选现实机构。 |
| 给出地点、环境、时代等条件，未指认文件 | 将全部条件交世界确定场景范围；具体地点可直接用于资料检索，宽泛条件由世界先补足到可建档的范围，再检索相应资料。 |
| 明确指定一份或多份事实 Markdown | 按文件管理协议第五节定位并读取指定文件，将其与用户附加条件一并交世界核对；指定文件作为主要场景依据，不另选无关场景。文件定位或读取问题按该协议报告，解决前不进入无资料兜底。 |

未指定文件时，运行器检索 `资产/永久资产/世界事实/` 当时实际存在的 Markdown，忽略 `.gitkeep`，按文件管理协议第五节从名称与正文提取范围、时间和来源；用户已明确交付的文件也可纳入本次检索。文件名或标题不符合某个样例不构成排除理由，无法确认且影响采用的范围才交世界返回缺项。指定文件不在默认目录时按用户提供的路径或附件读取，不自动搬迁或复制为永久资产。资料不足时，世界可按对象方法提出进一步核对需求。

先按文件管理协议处理指定文件与可选资料的读取问题，再按下表处理可用内容。文件总数不等于适用文件数：

| 可用资料情况 | 处理 |
| --- | --- |
| 没有事实文件，或有文件但均不适用 | 将“无适用资料”交世界，继续创建或补足场景；没有可选资料不阻塞初始化。真实地点的必要制度事实仍按世界方法核对。 |
| 只有一份候选资料 | 完整读取并交世界核对范围、日期和用户条件；相容才采用，不能仅因它是唯一文件就加载。 |
| 多份资料描述同一场景的相容部分 | 将相关文件交世界核对后组合使用，保留各自的来源和适用范围，不丢弃可兼容的通用约束。 |
| 多份资料指向不同地点或不同场景 | 先按用户条件或世界已确定的场景筛选；无条件时仍由世界创建场景，不混合互斥地点。用户明确要求从候选文件中自行选择时，世界在该范围内选择；用户指定了多份互斥文件且未授权选择时作最小澄清。 |
| 日期、范围或事实存在冲突，或指定文件与附加条件冲突 | 由世界依据适用时间、范围及来源核对；明确不适用的部分排除。影响建档且无法消解的冲突只询问冲突点，不能靠文件名、读取顺序或“更具体”直接覆盖事实。 |

世界初步创建场景与最终确认客观边界可分次调用，但均须在人物建档前完成。每次补充调用沿用已有草案和已确定条件；候选资料不适用时补足缺口，不反复更换场景。将已采用的具体局部约束、文件管理协议第五节要求的来源记录和本次生成的局部设定交世界纳入建档草案，随后与其余初始状态一同保存。

### 2. 请求独立人物

向角色发起建档调用，传入对象性别、必要环境约束和已明确提供的校验材料。角色按对象第十三节生成并检查人物，按交互协议分离私人内容与必要外部背景。

接收本主体检查结果。未通过时让角色局部修正受影响内容；运行器不代改人物，也不选择更讨喜的候选。

### 3. 请求社会位置与起点观察

人物独立成立后，只将必要外部背景交世界，发起“外部相容性与社会位置”建档调用。世界按对象方法核对并形成分主体起点信息草案。

将草案中的角色起点信息交角色作建档校准，保留需要后续处理的当前事项。正式建档保存后，这些已校准信息不再重复投递为新观察。客观冲突回到世界或受影响的建档步骤核查，不把完整私人内容交世界解决。

### 4. 取得建档确认

分别请求世界和角色确认各自内容。世界检查客观相容性；角色检查人物及其认识；运行器核对步骤二已先于步骤三完成，以及交接是否使用了正确接收方。

未通过时仅返回负责该内容的步骤并复核受影响的下游。必要资料缺失或权威无法解决的冲突，按根入口报告；合法人物缺少共同点不构成重建理由。

## 三、保存与首次推进

两个主体确认后，调用文件管理协议第六节保存程序，创建当前编号下的三份初始文件。起点背景及初始账本内容依状态协议处理，不在本 Skill 重定义。

保存完成后，将运行编号、起点、用户起点观察、已接纳安排与尚待处理的启动请求交推进 Skill 的“首次输出”入口；只交接该入口需要的授权材料。角色的最小调度信息由推进分支需要时查询，不为纯建议或起点展示提前唤起决策。人物的当前事项已经在本侧状态中，不另建初始化交接文件。

初始化期间若收到明确世界内行动或推进要求，建档后交同一个推进入口处理，不得据此反向定制人物。有建议请求而没有行动时，在起点提供候选并等待选择；没有这些请求就交还起点控制，不虚构用户输入或先跳时寻找交互。

复用推进 Skill 直至第一次输出完成。若已有合法建档但首次推进被阻塞，报告已保存的编号及具体阻塞；下次从该运行恢复，不再次建档。

## 四、边界与例外

只组织对象调用，不在此复制人物生成维度、世界补足方法、保存程序或停止条件。执行时使用其唯一权威正文。

候选比较与校验过程不成为人物经历。首次输出根据交互协议成立，呈现起点可知处境而不另加欢迎剧情或安排初次相遇；保存失败按文件管理协议处理。

## 五、执行形态示例

- 正常新建：世界边界 → 独立人物 → 社会位置与局部观察 → 分别确认 → 保存 → 首次推进及输出。
- 建档已保存，首次推进缺必要资料：报告当前编号和缺项；资料补足后用推进 Skill 恢复，不重复生成人物。
- 启动时附课表并请求“给今天下午几个安排建议”：世界核对课表 → 按原顺序完成独立建档并保存 → 推进 Skill 的辅助分支提供候选 → 在起点等待用户选择，不直接执行一周行程。
- 只说“开始模拟”：合并询问双方性别及基本身份 → 世界创建场景 → 无适用事实文件时继续建档 → 首次输出说明起点。
- 只给“普通大学校园，秋季学期”：世界在这些条件内补足场景 → 检索并接入适用资料；空目录也可完成，本地无关资料不参与。
- 指定“使用我提供的事实文件”：读取指定文件 → 世界核对附加条件及资料冲突 → 建档；文件缺失时先报告，不用自动生成场景掩盖缺项。
