# 推进

本 Skill 唯一规定一次输入到下一次输出的跨主体次序、范围接入及统一时间调度，包括不推进时间的查询、安排登记、行动辅助与资料维护分支。授权和停点定义引用交互协议，专业判断引用对象，写回引用文件管理协议；不另设主动行动或后台推进的第二套算法。

## 一、入口与准备

按 `AGENTS.md` 路由，确认已读三个协议；进入时间推进才需同时读取角色与世界对象，纯查询、安排登记或资料维护只需世界对象。触发行动辅助时另读助手对象：

- `协议/状态协议.md`、`协议/分权与交互协议.md`、`协议/文件管理协议.md`。
- `对象/角色智能体.md`、`对象/世界控制器.md`。
- `对象/用户行动助手.md`：只在第二节“行动与安排辅助”分支使用。

按交互协议第五节先识别整条输入的类别、限制与依赖，再执行分流。其他纯模拟外任务回根入口，不因没有运行而阻塞设计讨论。暂停或结束请求先停止实际推进；混合输入不把原始用户全文作为人物观察。

按文件管理协议定位并检查本次所需运行文件；需要推进时才由角色检查本侧状态。纯查询、辅助、安排登记或资料维护只检查所涉客观文件和用户可见上下文，不读取人物私人内容。记录本次起始模拟时间用于输出跨度；所有保存点调用文件管理协议第六节，失败走第七节恢复，不消费未保存成功的结果。

恢复或本次处理需要重新读取事实来源时，向世界查询已采用约束是否足够、适用时间及具体来源依赖，由运行器按文件管理协议第七节检查所需来源。查询可确认使用既有约束；需接纳新版、替代来源或补足依据时进入第二节“客观资料维护”，保存完成后再处理依赖它的请求。来源缺失或冲突只阻塞受影响步骤；不能为了绕过它跳过更早的必要节点。新增文件不自动接入当前运行。

## 二、接入当前时点

### 首次输出

只接收初始化已保存的运行及用户起点观察，不重复投递建档已吸收的信息。暂存的行动、推进或建议请求按下方“新输入与恢复”处理；已在建档接纳的课表不重复登记。没有这些请求时，进入第六节输出起点处境，可按第三节的方法查询有依据的单一后续范围，不先让人物或世界演进以寻找交互。

### 新输入与恢复

1. 向世界查询当前时点与本次所需的用户可知处境；候选选择先按交互协议第五节核对原选项、所指内容和当前条件，再还原为用户行动或安排。不能确定指向或重要条件变化时，进入第六节说明并等待确认，不自行执行修订版。
2. 纯当前信息询问只用世界查询结果回答，进入第六节，不读取角色调度信息、不启动时间推进。需要现实搜索、出行或发消息才能获得的信息，按交互协议识别为行动而不是查询；关键歧义先澄清。
3. 有资料补充或纠错时先走下方“客观资料维护”；有尚未执行安排的登记、修改或取消时再走“安排接纳”。改变正在进行的行为仍属于当前行动，留给第三节裁决实际效果。与后续行动有关的冲突未解决，就输出问题，不继续执行。
4. 纯建议或草稿修订请求进入“行动与安排辅助”。用户已明确提交完整行动时不转成菜单；实际行动、回复、等待及推进请求统一进入第三节，不绕过排序先完成耗时动作。

混合请求按已识别的先后与依赖连接这些分支。建议是执行前提时先给候选并停下；用户要求行动之后再给建议时，先按第三至五节处理获授权的行动，到停点后再辅助。没有独立行动或推进请求的输入处理完就输出，不因旧授权尚存而落入第三节。

回答、忽略或离开上次情境均作为新行动处理，不因存在旧问题而强制用户先作口头回答。只恢复而未要求继续时展示当前处境；要求继续但范围不可核对时按第三节处理。不得重裁旧输入、重投已处理观察或假定临时授权仍存在。

### 安排接纳

将用户明确提交的安排及其尚未执行部分的增改范围交世界“裁决与推进”，本次上限限定为当前时点，用途限定为核对安排，不启动其未来行为。接收并保存世界确认的更新；只登记安排不进入第四节生成虚构观察或执行记录。

只登记或调整未来安排时，进入第六节报告接纳结果及时间未推进。若同一输入还要求立即行动或推进，保存后进入第三节；新范围依据本次指令和仍有效的旧授权核对，不能把整张课表直接当作本次上限。对正在执行的行为作出的停止或改变属于当前行动，其实际效果仍须经第三节排序裁决。

### 行动与安排辅助

1. 按交互协议第五节核对触发是否成立。面前已有未确认候选而用户只说“继续”或“你决定”时，依原候选提示选择或手动输入，不调用助手重复生成。
2. 通过世界查询取得本次可交付给用户的处境、相关已接纳安排与所需现实条件。与用户的明确要求、猜测标记和待改草稿合并为授权材料；不查询角色私人计划，也不把原始世界文件交助手。
3. 调用助手“行动与安排建议”，由对象文件的方法生成或修订。助手返回缺项时，只对尚未查询且可由世界核对的事项补一次查询；若有新材料再交助手，否则向用户说明最少缺项，不循环查询未知信息。
4. 将候选或缺项作为本次已处理的辅助结果交第六节输出，不交世界执行、不保存成用户安排。后续选择与手动输入重新从“新输入与恢复”进入；本分支不维持自己的执行队列。

### 客观资料维护

1. 接收用户要求用于当前运行的资料或纠错请求，或前述来源检查及世界当前处理提出的核对需求。按交互协议第五节区分当前运行接纳与永久资料维护；文件定位与读取问题按文件管理协议第五节处理。将材料、用途、适用范围和来源依据交世界“资料核对”，不夹带期望的关系结果。
2. 世界按对象第十三节返回接纳、无需变更、未采用、缺项或冲突结论。未解决且影响后续行动的问题先报告，只处理不依赖该问题的部分。资料涉及实际外部变化时保留世界确认的时间与待处理条件，只有合法进入第三节时才按统一排序裁决；不在资料维护中直接落实变化的后果。
3. 有合法修订时调用保存程序；无变化则不制造写入。不得把此结果交第四节当作新世界事件或自动投递给角色。
4. 纯维护请求经第六节报告核对与保存结果，明确模拟时间未推进，然后停止。混合请求完成维护后返回本节分流，继续处理独立的安排、建议或行动部分；资料修改使旧范围失效时重新核对授权。由来源检查或当前世界处理提出的内部核对完成后，返回原步骤重新查询尚未处理的事项，不重演已完成过程；依据仍不足时报告具体缺项，不循环重试。

## 三、统一调度

本节处理所有时间推进，包括用户行动、角色意图、正在进行的外部过程和无主动行动时的演进。两个主体只提供本侧信息；运行器按以下程序比较，不读取私人计划正文。

### 1. 接入授权范围

按交互协议第五节，从当前输入及仍可核对的既有授权确定本次范围，再用已接纳安排与世界查询核对现实耗时、当前阶段和有限结束条件。已保存的未来安排提供约束，不自动提供跳过中间时间的许可。

- 明确时间或有限活动范围：采用该范围，核查更早需要用户选择的限制；结果不保证发生的等待不能自行变成无限范围。
- 当前行动或正在交流：处理该行动阶段及同一交互的正常后续；按交互协议核对中途暂停前是否仍有有效剩余范围，并在交互结束后续接。不能凭本次回复凭空扩展成数日等待。
- 单独继续或不操作：核对交互协议允许承接的活动、剩余授权或已展示单一范围；缺少依据就转第二节“行动与安排辅助”，不先查询角色决定或跳时。已有待选行动则先要求明确选择。

用户安排的核对与保存经第二节完成后才进入调度；到点执行仍需重新核对实际条件，不能把登记视为已实施。实际推进上限可从有限阶段逐次求得，不要求预知人物的回应；不得为追求互动扩大原授权。

需要展示单一后续范围时，只向世界查询用户可知的当前活动、明确安排、已知下一参与节点或现有外部过程的有限结束条件；确认该范围没有替用户新增待选行动。无法取得时不硬造范围；达到辅助触发条件才转第二节，否则输出当前处境并保留手动输入入口。候选范围只在第六节展示，不据此执行，也不以角色私人唤起时间替代。

### 2. 当前事项与准备动作

先检查本次已产生的现实节点，或已结束且需要用户重新选择的行动阶段；成立立即进入第六节，不再发起角色决策。尚未处理的新用户输入不等于一个必须重复展示的旧停点。

没有新现实节点且已取得推进授权时，再查询角色的最小调度信息。已有客观过程的到点变化先走下方“每次世界裁决前的排序”；角色的新观察、到点计划或未决事项按交互协议第四节走第五节。只有已就绪、只待落实且未受新合法触发影响的意图才直接沿用，不把未来私人计划当作必然执行，也不为了取得同一意图重复决策。新用户行动走同一个排序入口。

每次结果都回到此处重查。只有已到执行条件的待落实意图进入裁决；未来选择不阻挡当前到界返回。未到时点的用户明确安排、角色待落实选择或进行中过程保留在所属状态，不能反复提交已经受理或完成的同一动作。条件未变且同一时点未能执行的意图暂缓，先处理阻碍它的已到点事项，不靠重试使其成功。

当前阶段结束后先复核原范围的未执行部分；仍有效才继续，缺少后续授权、范围已取消或到界且当点事项处理完毕时进入第六节。否则按下方程序处理下一时点，不另开后台循环。

### 3. 每次世界裁决前的排序

1. 世界查询待提交动作及现有过程，给出当前需处理的客观变化、下一候选时点、动作耗时和阶段条件。角色查询下一唤起时间及当前就绪情况；状态未变化的同一查询结果可复用。
2. 将世界候选、角色唤起、用户明确安排的到点时间与授权范围的时间或阶段上限一起比较，取最早需处理的时点。尚未落实的当前动作先核对当前可开始的部分；已经到点但未处理的事项按当前处境核查，不忽略，也不倒退时间补演历史。
3. 只将外显意图、必要外部条件及本次时间上限交世界“裁决与推进”。人物时间只用于限制本次跨度，不提交其私人原因。多项同刻外显行为由世界裁决客观并发，不凭调用次序给予成功保证。
4. 世界返回截至上限的实际结果，也可因新出现的更早变化提前返回。随后统一进入第四节，再回本节检查当前事项；不直接连续调用世界越过角色应处理的时点。

只有授权边界到达而没有事件时，也由世界确认实际时间与必要连续性，不追加“无事发生”事件。确无可处理时点、范围不能确定或存在无法核查的时序冲突时，使用交互协议对应的状态输出，不虚构触发打破停滞。

世界因本次确需的新事实依据返回核对需求时，纯查询提出的需求可直接进入第二节“客观资料维护”；若裁决已经产生部分现实结果，先经第四节保存并分发观察，再回本节检查用户停点，只有仍可继续处理时才接入资料维护。核对结束后从尚未处理的事项继续排序；缺项未解决就按对应返回条件报告，不使用猜测的新制度完成动作。

## 四、处理世界结果

本节只接收第三节正式调度产生的世界结果；第二节只登记安排的结果在本分支外保存，建档草案与模拟外资料核对也不进入本节。

1. 调用保存程序，写入世界确认的客观变化及事件。
2. 分发该时点实际可得的观察。角色收到新观察及自身动作的实际反馈后执行“吸收观察”，更新当前状态和执行情况，不立即生成新外显行为。
3. 调用保存程序保存角色变化；同一已处理观察不重复投递。
4. 保留用户合法观察，回第三节先检查用户控制，再处理当点事项或下一时点。

未来未完成的外部过程、用户已明确安排和人物当前事项只存于状态协议指定位置；运行器不另建调用队列或把预测结果提前记入经历。

## 五、处理角色决定

仅在第三节确认合法决策依据后调用角色，按对象第五节判断。运行器不代做记忆检索，不改写语言或要求改选。

接收并保存人物私有变化。无新行动是已完成的决定，不留作待重试任务；有外显意图则交回第三节统一排序，不直接交世界完成整个动作。停点前尚未落实的选择由角色当前状态承接，已有实际反馈则依第四节更新，不因暂停重复执行。

## 六、保存与输出

先确认截至停点的必要保存已经完成；失败时只走下方失败处理，不继续调用助手。若还有用户明确要求且尚未处理的后续建议，并且它依赖的前置行动已经完成，调用第二节辅助分支一次，将已处理结果合并到本次输出，不再次调用助手或返回时间调度。更早节点打断前置行动时，不把该行动当作已完成来给建议。

按交互协议第六节输出当前时间、必要处境和本次实际推进跨度。现实观察、查询答复、安排登记、行动建议、待确认范围和执行问题分别标清，不把系统说明写成人物台词；不推进时间的分支明确时间未变。

需要下一段授权时，只用第三节取得的用户可知单一范围或第二节助手返回的候选，不由运行器自行编排选项。前者说明上限及提前返回条件，后者保留助手提供的选择与手动修改入口；已有有效授权覆盖后续时不重复征求授权。输出后立即停止实际执行，待选行动与待确认范围按交互协议区分，不把暂停等同于取消安排。

保存失败时报告实际落盘情况与问题，不显示未提交结果。跨会话无法核对上次范围或候选时说明缺项并重新确认；不从隐藏状态猜测原授权或编号，不为避免询问另存候选历史。

## 七、边界与例外

用户主动行动不保证相遇，也不需要证明其动机与人物无关；人物只收到世界确认的可见信息。角色无新行动不等于必须跳时，反复旧观察也不产生新决定。

纯时间边界上按交互协议处理已到点事项；若它们生成现实节点就交回控制。边界后才能完成的动作只保存已开始的过程或尚未落实的选择，不为完成动作越界。

模拟外维护不启动推进；世界内新行为不冒充记录纠错。缺少必要资料、权限或恢复依据时报告具体缺项，不重新建档掩盖问题。

## 八、执行形态示例

- 当前聊天：用户言语 → 第三节排序 → 世界裁决并按第四节保存、投递 → 角色吸收 → 无须立即返回时作决定 → 再经第三节裁决表达 → 输出。交互结束且无后续授权时给当下处境，不自动跳到下次相遇。
- 主动出行：用户说“现在去图书馆” → 核对行动范围并排序出行、世界变化与人物唤起 → 处理实际观察 → 到达后的下一步未授权时交回控制。没有看见人物也正常输出，不自动扩展为搜索、守候或搭话。
- 已展示“可推进到 16:00 课程开始”后用户说“继续”：以该范围运行，15:05 若出现用户节点就提前输出，否则到界报告实际情况。显示时间不揭示角色私人安排。
- 用户模拟外补充专业：世界资料核对 → 保存合法客观更新 → 报告时间未推进；不追加一次虚构谈话，不让人物自动得知。
- 用户提交某场所的制度文件并要求用于当前运行：读取资料 → 世界核对地点、生效时间及已有历史 → 保存相容的局部约束和来源 → 报告接纳范围；涉及冲突则先报告，不修改永久资料或人物认识。
