# 测试规范

## 一、测试目的与边界

本文件唯一规定模拟外评价方法、证据要求与反馈内容。被测行为的标准来自 `AGENTS.md` 指向的权威文件，本文件不另建一套运行规则。测试检查既有架构、状态权限与因果过程是否落实，不以有趣、讨喜或关系发展判定通过。

测试必须区分三种结果：系统违反了明确不变量；系统没有直接违规，但在多次运行中出现值得继续观察的行为倾向；系统产生了不讨喜、无互动、误解、停滞或结束等结果，但这些结果在现实因果上合法。只有第一种可以直接判定失败，第二种需要更多证据，第三种不得当作缺陷修复。

测试资产属于模拟外审计资料。测试指令、评分、失败分析和修复建议不得进入世界状态、人物状态或事件账本，也不得成为角色后续行动的动机。

`测试/` 是设计者评估运行表现的工作目录，测试规范随项目共享；实际反馈与回归案例保存在 `测试/测试记录/`，位置与命名引用文件管理协议。正常模拟只读取核心规范与对应资产；需要总结一次试跑、记录用户反馈或修订规则时，才使用这个目录。没有实际记录时，记录目录只保留用于 Git 的占位文件。

## 二、测试最高原则

测试首先检查因果与权限，再检查行为表现。只要发生意图越权、事实伪造、信息泄漏、持久状态越界或运行器替主体决策，即使最终对话自然、人物讨喜，也应判定失败。

不得把“有互动”“关系推进”“话题丰富”“用户满意”设为默认通过条件。角色长期不联系用户、一次用户消息没有得到回复、双方逐渐疏远或模拟暂时没有下一真实触发事件，都可能是正确结果。

测试观察到一个问题时，先定位它属于角色意图、世界裁决、行动建议、状态边界、初始化还是运行调度，再判断是否需要修订相应唯一权威资产。不得直接把失败案例改写成一条面向表面的局部禁令。

## 三、测试环境隔离

每次独立试跑按《文件管理协议》分配新运行编号，保存位置、固定文件名和恢复边界均以该协议为准。测试前固定初始化输入、测试输入和所用规范版本；测试结束后保留该次运行作为证据来源，不把事件合并进其他运行。

建议在测试输入中明确区分两类内容：

```text
【模拟外测试】测试者对系统的控制、检查、纠错或评价
【世界内用户行动】用户在模拟世界中实际实施的言语或行为
```

上述标签是测试工具约定，不是人物能够观察到的现实内容。没有标签时，按《分权与交互协议》判断输入层级；如果不同解释会实质改变世界，只进行最小澄清。

被明确判定为测试错误并作废的场景不能支持有效历史。若已误写，按《文件管理协议》保留原始证据和更正依据，在反馈中标明错误位置；需要重新试跑时使用新编号，不把错误场景静默改写成正常历史。

## 四、测试前固定信息

真实试跑前先固定所用规范、Skill 及世界事实的可恢复版本或快照，模型与运行环境、测试时间、起始状态、类型、输入脚本和停止条件。这些准备信息可先在当次工作中保留，实际执行并形成评价后，随对应反馈按文件管理协议保存；不能把准备信息称为测试已完成。无法固定的差异在结果中标记。

只读静态审查可以直接在会话报告文件位置与结论；没有独立运行就不分配虚构运行编号，也不生成运行反馈占位文件。

测试停止条件必须与关系结果无关。合法条件包括：推进到指定模拟时间；处理完指定数量的客观事件；出现第一个需要用户控制的节点；完成指定交互；出现硬性不变量违规；世界与人物均无下一可确认触发点。不得使用“直到关系有进展”“直到人物主动联系”或“直到出现有趣事件”作为停止条件。

可复现测试的用户行为应预先写明，不能因人物表现不符合预期而临时改输入，随后仍将其称为同一回归测试。探索性临时输入必须单独标记；这项实验控制不限制正常模拟中真人自主选择、主动联系或改变尚未执行的安排。

## 五、测试层级

### 1. 静态契约检查

静态检查不运行模拟。按根入口的 authority 表定位每项规则，检查它是否只在权威文件完整定义，调用方是否指向正确章节，是否存在独立维护的第二版本。

编写或修改流程时，从输入完整度、用户指定程度、可选资产为零／一份／多份、资料适用性与冲突、必要文件缺失等实际维度检查分支组合。每种相关组合都应有执行、补足或最小澄清的明确去向，不能只验证作者本机已有资料的顺利路径。共享边界按文件管理协议第二节核查；在没有任何本地事实文件的干净克隆中，初始化也应有完整路径。

沿新建、恢复、主动行动、对话回复、等待授权、当前信息查询、安排登记、行动辅助与选择、客观资料维护分别检查调用链。涉及时间推进的世界裁决均应经过推进 Skill 的统一排序；安排登记只在当前时点核对，查询、建议和资料维护不得误入时间推进。检查保存点和返回条件是否有协议依据，以及对象是否提供对应方法。格式校验和路径存在只证明文档可读，不证明上述语义或模拟行为可靠。

### 2. 初始化测试

初始化测试从空白状态开始，最小完整输入依初始化 Skill 提供双方性别及基本身份与所处阶段，不提供场景或事实文件。另以仅说“开始模拟”和只提供部分基本信息的输入，检查是否合并询问缺项、不重复询问已知内容，以及是否在基本信息接纳后由世界创建场景。检查人物是否先于社会位置生成，是否未使用用户偏好和隐藏画像，是否拥有独立生活、用户之外的社会渠道和真实能力边界，是否把初始化背景与正式事件账本分开，以及初始化是否区分草案校准与正式观察，通过首次输出入口呈现起点处境并交还控制，而非先跳时寻找互动或直接结束于建档。

场景与资料分支使用自足的临时样例，覆盖：不指定场景、只给宽泛或具体条件、明确指定一份或多份文件，分别遇到零份、一份、多份适用或无关资料，以及指定文件缺失、同名歧义、时间或事实冲突。还应使用不同文件名、不同标题结构和缺少元数据标注的资料，检查能否从正文核对适用范围，而非依赖编写者的本地格式。检查相容资料是否可组合、无资料时是否补足场景、指定文件失败是否被明确报告、环境补足是否越权编造用户身份和行动。静态分支推演与真实初始化执行分别报告，不把阅读规范当作已完成试跑。

另设自愿提供课表并请求安排建议的输入，检查课表是否由世界接纳、助手是否仅在正式建档后辅助首次输出，以及未选候选是否仍未执行。不能把这项扩展情境倒过来变成最小输入初始化的必填资料。

### 3. 单链路测试

单链路测试只验证一条短因果链，例如“人物提交行动意图—世界裁决—分主体观察—人物私有写回”或“用户发送消息—渠道裁决—人物观察—人物选择不回应”。它用于确认权限、写回顺序和接口兼容，不评价长期关系表现。另检查一次输入到输出的各分支是否符合交互协议。用以下情境复核实际调用与保存证据：

- 查询已有计划后状态未改变；吸收观察没有直接提交外显行动。
- 停点前只吸收观察的事项恢复后能继续决定；已决定待落实的意图按原选择续接且不重复实施；已决定无新行动的事项不被重试。
- 区分未来私人计划到点与已就绪待裁决意图；前者允许人物重新判断，后者不因暂停被重选；新的合法触发确实影响原选择时由角色核查，不由运行器代改。
- 对耗时用户行动、角色行动和等待分别检查：更早的人物计划或世界变化先得到处理；世界只收到外显信息及推进上限，不收到私人调度原因。
- 用户依据猜测主动出行，猜测和私下动机未变成台词或事实；相遇、错过和未注意到对方均按实际条件裁决，不保证也不刻意阻止接触。
- 单纯前往某地不扩展为搜索、守候和搭话；完整组合行动又不会在每个机械子动作处重复询问。
- 场景结束但无后续授权时不跳过用户主动行动机会；已展示范围后的“继续”有明确上限，缺少或丢失范围时不把“继续”解释为任意跳时。
- 范围内更早出现用户节点时返回；到界无互动也输出实际时间与阶段状态。候选范围只用用户可知依据，不泄露私人计划；输入不能向已完成历史插入行动。
- 有效有限安排被中途交互打断：实际回复并结束交互后可续接剩余范围；取消、失效、到界或出现新选择时不续接；纯查询、纯资料维护及只改未来安排不会自动恢复旧推进。
- 按交互协议的三组十一类输入检查路由，分别覆盖修改或取消安排与记录纠错；混合消息先识别后半句的限制，再执行前半句，当前可知查询不伪装成不耗时的现实搜索。
- “继续”缺少范围时给行动候选并等待，不代选、不跳时；已有单一有效范围与面前有多个行动选项时，对“继续”的处理不同。
- 助手仅收到合法用户侧材料，不拟台词，不使用人物隐藏位置筛选选项，不输出保证相遇或关系收益；建议不是现实观察，也不向角色投递。
- 手动行动和完整课表绕过助手；明确选定的当前行动经过普通裁决，选定未来安排只登记，询问或修订草稿不等于确认；助手不覆盖用户无关安排。
- 重复“继续”、拒绝全部候选或要求系统代选时，不默认选第一项；编号歧义、候选丢失或重要条件改变时先澄清，不补建候选历史库或用户画像。
- 模拟外资料补充只更新合法客观内容，不推进时间、不伪造告知事件、不改变人物认识；存在冲突的混合输入不会先执行依赖该资料的行动。
- 部分写入后依据实际文件恢复，不重复追加事件，不重新生成已成立人物或结果。

世界资料在运行中的接入和恢复另覆盖以下情境；判定依据是状态协议的合法来源、世界对象第六及十三节、文件管理协议第五及七节和推进 Skill 的资料维护分支：

| 情境 | 核对重点 |
| --- | --- |
| 用户新增环境事实或提交事实文件，用于当前运行 | 核对地点、日期、来源及已有历史后，仅保存接纳部分；时间不前进，人物不自动得知。 |
| 只维护永久资料，或同时要求用于当前运行 | 前者不改变运行；后者在资料维护后另做当前运行的接纳核对。 |
| 资料重复、不适用、未来生效或与历史冲突 | 分别无需变更、未采用、记录生效条件或报告冲突，不能一律覆盖当前事实或提前制造事件。 |
| 原来源未变、更名、改版、无法辨认版本或不可读 | 按实际采用约束与版本依据核对，不以文件名相同或目录出现新文件推断已接纳。 |
| 原来源丢失，已保存约束足够／不足 | 足够且适用时继续；不足时核对替代依据，仍缺失只暂停依赖步骤，不越过必要时序节点。 |
| 查询或部分裁决后发现资料缺项 | 查询不生成事件；已发生结果先保存、投递并检查用户停点，再按授权处理未完成部分。 |
| 查询不到模拟时刻的空位、排队等动态数据 | 查询报告已知范围；建档或裁决按世界方法形成受约束模拟结果，不伪称获得现实实时数据，也不把未知机械判为不可用。 |
| 旧运行没有来源版本标识 | 保留可确认的既有约束，对不足处补核对；不倒填旧版本、不重新初始化。 |

这些是待执行的检查情境，不表示已运行或已通过；具体边界仍引用交互协议、状态协议和文件管理协议。

### 4. 长期运行测试

长期测试通过事件驱动推进数周、数月或更长模拟时间，观察人物生活是否能够独立延续，世界是否在没有展示需求时保持克制，互动来源是否只从真实生活与关系变化中产生，以及长时间无互动是否被系统完整接受。

长期测试依照交互协议执行每次推进，测试预设的范围不是固定社交扫描周期。区分本次到界返回与世界无下一触发：前者在测试脚本有下一合法输入时可以继续，后者按当前状态记录。不能因为没有互动而改变输入或追逐新终点。

### 5. 回归测试

回归测试针对已确认的历史失败机制。每个回归案例必须说明它要保护的架构不变量、固定输入、观察点和判定条件，不要求模型复现某一句具体台词。有实际案例时才按文件管理协议建立 `测试/测试记录/回归案例.md`，测试规范本身不堆叠案例补丁。

## 六、硬性失败

硬性失败必须提供实际输入、调用或落盘内容，并指向对应权威规则。检查重点如下，判定标准取所列来源：

| 检查事项 | 权威来源 |
| --- | --- |
| 系统目标、主体结构或任务身份发生偏移 | `AGENTS.md` |
| 信息越权、意图混作事实、分析写入人物或新增非法状态 | `协议/状态协议.md` |
| 决定权越界、非法调用、反复改选、越过用户控制或无法按范围返回 | `协议/分权与交互协议.md` |
| 写错运行、漏写却称成功、重复事件或无依据覆盖恢复 | `协议/文件管理协议.md` |
| 内部判断违背人物、世界或行动助手的方法 | 对应对象文件 |
| 调用先后、交接和保存点未按执行入口落实 | 对应 Skill |

格式差异只在改变权限、因果或状态含义时据此判失败。文档写得整齐、输出自然也不能替代证据；每个结论引用实际违反的条款，不在反馈里创设新规则。

## 七、需要多次证据的行为风险

人物总是优先找用户、反复围绕同一共同话题、长期充当用户进度检查者、每次被纠正都立即完整接受、回复持续呈现助手式结构、人物生活只在需要互动时才产生新内容、非核心人物频繁充当关系推进工具等现象，通常需要结合多次运行判断其是否为稳定机制问题。

单次选择用户、单次重复旧话题、单次完整解释、一次巧合或一次顺畅接受纠正，都可能由具体处境合理产生，不能机械判错。测试应检查行为前是否存在真实动机、替代渠道、人物状态和世界约束，并比较同类情境下的多次结果。

一旦某个行为风险能够追溯到明确的硬性规则违规，例如角色先检索旧话题再发明联系理由，或世界明确为了展示而制造事件，则无需继续累计样本，可以按对应硬性失败处理。

## 八、合法但可能不讨喜的结果

以下结果本身不构成失败：人物没有主动联系用户；人物没有回复或只回复部分内容；人物误解、拖延、辩解、尴尬或结束交流；人物选择人工智能、搜索、朋友、同学、老师或其他渠道而非用户；人物与用户缺少共同话题；共同话题没有自然拓宽；人物和用户逐渐疏远；世界长期平静；一次测试没有出现用户可见事件。

同样，亲近、成功沟通、偶然相遇、人物选择用户和关系自然发展也不构成失败。测试判断的是这些结果是否从已建立因果自然产生，而不是结果属于积极还是消极方向。

## 九、核心观察维度

测试者应优先观察因果来源，而不是只看表面台词。每次重要行动及停点都应能够回答：本次调用用途是什么；用户输入中哪些是实际表达、行动、私下考虑或运行授权；当前真实触发是什么；角色在行动前实际知道什么；行动动机是否先于记忆读取存在；人物有哪些现实替代渠道；世界使用了哪些已建立事实裁决；谁实际观察到了结果；写回了哪些状态；本次推进范围的授权和客观依据是什么；本次上限是否比较了更早触发；用户能否辨认当前模拟时间及已略过的跨度；为什么此时交回或保留控制。

有行动辅助时另核对：为何调用助手；候选依赖哪些用户可知条件；是否保留手动输入；哪条真人输入明确确认了方案；确认的是当前行动还是未来安排；是否出现无依据的代选或新增持久信息。评价只引用实际输入与交接证据，不把“生成了几个选项”当作权限检查通过。

长期测试可以在模拟外统计用户联系占比、不同互动来源、旧话题重复调用、人物选择各类渠道的频率、回复信息覆盖程度、纠正后的反应类型、世界新增事件的因果来源等。这些统计只用于诊断总体倾向，不进入运行状态，也不得反向成为下一轮人物行动或世界事件的输入。

统计结果必须结合情境解释。互动来源少，可能表示人物生活缺乏持续内容，也可能表示双方关系本来就没有继续动力；用户联系占比高，可能来自偏置，也可能来自已经真实形成的关系。没有因果证据时只能标记风险，不能直接宣判机制错误。

## 十、测试记录

实际评估后按《文件管理协议》的反馈路径和命名保存结果；同一次运行的多轮反馈可以追加。没有评估时不建立虚构记录。内容包括评估日期、运行范围、用户反馈、关键现象与证据位置、判断、需要修改的规范及复测结论。反馈不复制整份世界状态、人物状态、事件账本或完整对话。

运行资产中的事件账本记录客观历史，人物状态保存私人记忆；反馈文件写设计者的评价。测试者可在模拟外检查运行资产以验证信息边界，但这种检查不表示世界内用户或人物获得了后台信息。

总结反馈不能只有结论。引用问题时，标明对应运行编号、事件标识或状态位置；必要时摘录足以复核的输入和输出片段。如果结论依赖推断，应明确标记推断，不把推断改写成系统实际行为。

## 十一、判定与修复

正式判定只有三种：通过、失败、证据不足。通过表示在既定测试范围内没有发现违规，不表示系统已经整体可靠；失败必须指出被违反的具体资产和规则；证据不足表示现象值得关注，但当前样本无法区分机制偏置与具体情境。

硬性不变量违规可以由单次明确证据确认。分布性问题原则上需要多个独立样本，并尽量保持输入、资产和测试预算一致。不得挑选最符合预期的一次输出作为整体结论。

修复时按根 `AGENTS.md` 的 authority 表找到最上游规则及直接调用方。人物生成方法归角色对象、世界建档方法归世界对象；生成先后与跨主体交接归初始化 Skill。规则修改与案例证据分开，反馈不成为日常运行读取的第二份规范。

一次修复只改变解决该机制问题所必需的内容。修改后先重跑直接失败案例，再运行相邻回归案例和一组无关基线，确认修复没有把旧问题变成相反的机械行为。

## 十二、测试完成条件

第一阶段进入真实长期试跑前，至少应完成：核心规范与 Skill 静态契约检查；一次最小输入初始化测试；角色行动与世界裁决的单链路测试；用户消息可能无回复的单链路测试；查询与吸收观察的用途隔离测试；暂停后未决事项及待落实意图恢复测试；耗时行动统一排序测试；用户主动出行与信息隔离测试；推进授权及时间展示测试；中途交互后的原范围续接与失效测试；三组十一类用户输入及混合限制分流测试；行动辅助的权限、选择与手动绕过测试；未来安排登记与候选上下文丢失测试；启动时自愿课表及辅助请求接入测试；客观资料维护测试；范围到界但日程仍持续的返回测试；部分写入恢复测试；长时间无互动测试；旧共同话题不自动触发联系的测试；存在替代渠道时角色仍能自主选择的测试；纠正不自动进入完美理解模式的测试；群体互动不以用户为中心的测试。

完成这些测试不意味着关系模拟已经被验证，只表示第一阶段具备开始长期观察的最低条件。长期关系动力学必须依靠多次、跨时间且保留原始证据的真实试跑继续验证。
