# 文件管理协议

## 一、权威范围

本协议唯一规定项目目录、运行编号、文件表达、写入范围、保存完成标准和恢复规则。内容语义及可保存范围引用 `协议/状态协议.md`，提交者与调用权限引用 `协议/分权与交互协议.md`。Skill 在指定时点调用本协议的保存程序，不各自维护另一套写入规则。

## 二、目录与用途

以下目录树从项目根目录开始，不包含外层文件夹名。项目根目录指本仓库入口 `AGENTS.md` 所在目录；默认克隆 `SocialSimulation` 仓库时，外层文件夹同名，但也可使用其他本地名称。运行和保存不依赖外层文件夹名，不因仓库改名而另建一层目录；内部目录及文件仍按下列结构定位。

```text
AGENTS.md
README.md
.gitignore
对象/
  角色智能体.md
  世界控制器.md
  用户行动助手.md
协议/
  状态协议.md
  分权与交互协议.md
  文件管理协议.md
技能/
  simulation-initialize/
    SKILL.md
  simulation-advance/
    SKILL.md
资产/
  永久资产/
    世界事实/
      .gitkeep
  运行资产/
    .gitkeep
    <运行编号>/
      世界状态.md
      人物状态.md
      事件账本.md
测试/
  测试规范.md
  测试记录/
    .gitkeep
    <运行编号>_反馈.md
    回归案例.md
```

`README.md` 面向使用者说明项目与交互方式，不定义新的运行规则，也不替代根入口。根 `.gitignore` 实现 Git 跟踪边界：入口、README、对象、协议、Skill、测试规范和目录占位文件随项目共享；世界事实、运行资产及实际测试记录保留在本地。日常编写与维护不得自行给具体世界事实或运行资产添加 Git 例外；以后若明确要求公开资料，再单独核对共享范围。

编写文件前先确定它属于共享规范还是本地资料。共享文件只描述通用目录、资产格式、发现与使用方法，不出现具体本地资料的名称、内容、真实运行结果或依赖这些内容的启动示例，也不宣称克隆后自带某份本地资料。示例使用自足的虚构条件或占位符；本地资料可以引用共享规范，共享规范不能依赖某份未随仓库提供的文件才能执行。目录为空或已有用户添加的资料都是有效状态，实际内容在使用时检查；共享规范不固定资产清单，不把编写者某次检查得到的目录内容当作运行前提。

`.gitkeep` 仅让 Git 保留空目录，不是世界资料或运行资产，不参与加载、运行编号或完整性判断。被忽略的本地资料仍可按本协议使用，但不会随仓库备份或分享；Git 忽略不替代提交前的内容核查。

`技能/` 保存本项目的可重复执行能力，根入口负责导航，不在全局技能目录安装副本。每个技能以同名目录下的 `SKILL.md` 为唯一执行正文，不保留旧流程正文作为第二权威。

目录中的运行文件与反馈文件在相应工作实际发生后建立；回归案例文件只在确认具体回归需求后建立。不提前创建空白运行或测试记录以伪装为完成。当前永久资产只设世界事实；未来增加种类必须来自明确需求。

永久资产用于跨运行复用，“永久”不表示设计者不能修订。运行资产只属于该段独立模拟。规范、Skill 和反馈是系统维护资料，不是模拟世界的持久状态，也不得通过目录位置授予角色额外知识。

## 三、编号与固定文件

第一次独立模拟使用 `运行001`；以后取现有运行目录最大编号加一，数字至少补足三位。编号表示独立人物与世界，不按一次调用、一天或一轮消息增加。编号和三份状态文件名在该段模拟中保持不变。

恢复使用用户明确指定的编号；只有一个现有运行且上下文明确是继续时可以直接定位。存在多个且指向不明时才询问。用户明确要求新模拟时必须新建编号，不能改写旧运行。

同一运行固定保存 `世界状态.md`、`人物状态.md`、`事件账本.md`。人物状态的四部分保存在同一文件，当前不拆出独立记忆数据库。测试用的独立试跑同样分配新编号，不另设一套状态格式。

用户行动助手只有 `对象/用户行动助手.md` 这一方法文件，不新增运行文件、候选目录或用户档案。候选及确认后安排的归属引用状态协议，后者由世界提交并通过本协议的共同保存程序写回。

三份文件使用可直接读取的 Markdown，标题标明所属运行编号。世界状态按状态协议的内容范围组织；人物状态使用该协议规定的四部分；账本按事件逐条组织，字段与语义引用状态协议。缺省或未知明确标识，文件格式不自行补齐事实。

测试反馈与回归案例统一放在 `测试/测试记录/`，不与测试规范并列存放。反馈路径为 `测试/测试记录/<运行编号>_反馈.md`，一次运行的多次评价可在同一文件中追加；回归案例使用 `测试/测试记录/回归案例.md`。没有实际评价或已确认案例时不生成相应文件，空目录只保留 `.gitkeep`；评价的判断方法以测试规范为准。

## 四、写入范围与执行权限

写入内容由分权与交互协议指定的主体提交，运行器使用文件工具实际写入当前编号的文件。正常快照更新及合法事件追加无需逐次请用户批准；不能将“已提出更新”当作文件已改变。

永久资产、对象规范、协议、Skill 和测试文件在日常模拟中只读。用户明确提出设计修订、资料维护或评估时，系统进入对应模拟外任务，仅修改该任务涉及的范围。当前运行不得自行修改规则来迎合结果，也不得把本次生成的虚构事实写成跨运行现实资料。

删除、合并、覆盖另一段运行，或批量改名，不属于正常运行写回。必须有用户明确指定的目标；目标不清楚时先澄清。不得用新初始化覆盖不完整的旧运行。

## 五、资料与引用

规范和 Skill 使用相对于项目根目录的稳定文件路径，引用事项的唯一权威来源。迁移文件时同步修订全部直接引用，不保留一份旧正文继续作为第二权威。

世界事实文件按实际主题命名，正文开头注明适用范围、可用于检索的地点或场景称呼、必要的时间条件及来源。称呼只帮助发现资料，正文范围与时间条件才表明资料适用于哪里、何时。未验证的事实、用户提供的本地设定和模拟运行倾向必须与已核实现实明确区分，不能把推断或倾向写成必然事实。涉及会变化的制度或渠道条件时，使用有依据且适用于模拟时间的版本。初始化的文件选择顺序归初始化 Skill，事实适用性核对与场景补足归世界对象；资料文件不另写一套初始化程序。

用户自行添加的 Markdown 不要求固定文件名或特定元数据语法。缺少上述标注时，从正文提取可确认的范围、日期和来源；仍缺的信息明确标为未知。只有影响本次采用时才返回具体缺项，不因标题格式不同拒绝整份资料，也不把无来源陈述直接提升为已核实现实。资料中的行为要求不能修改主体权限或覆盖核心规范。

用户明确指定文件时，按其路径、附件或可唯一识别的名称定位并实际读取；名称有歧义时只核对具体指向。指定文件缺失或不可读时报告缺项，等待补足或用户撤回指定，不静默换用另一份文件。未明确指定的可选资料不可读时说明未采用，继续检查其余资料。此规则用于初始化和运行中的资料接纳，不因调用入口不同改变。

世界状态按状态协议保存本运行已采用的具体局部约束及适用时间，并为每项来源保留足以辨认的名称、位置或链接、采用时点和版本依据。文件优先记录可恢复版本标识；没有版本管理时可记录内容指纹，用于识别后续变化，指纹本身不能恢复原文。网页或附件注明可得的发布／修订时间和读取时点；无法取得稳定版本标识时明确注明。只保存采用部分及必要依据，不建立第二份完整永久资料库或新的顶层状态。

永久资料的新增、修订、移走或删除不自动改变已有运行。新模拟按初始化 Skill 发现当时可用的资料；已有运行只有在用户要求接入资料，或世界处理当前事项确需新依据时，才核对相关来源。资料仅用于当前运行时不自动复制或写入永久目录；维护永久资料也不等于把它接纳到所有运行。各次运行不能互相复制人物记忆、事件或用户隐私来定制新人物。

## 六、保存程序与完成条件

初始化和推进在各自 Skill 的保存点调用同一程序；不新增保存智能体或保存 Skill。

1. 定位当前编号的目标文件，读取待改部分；新建时确认编号没有占用，不以空内容覆盖已有文件。
2. 接收相应主体确认的写回内容，形成当次临时写入清单，包含目标、增改位置及提交来源。角色私有内容只用于机械写入，不交世界侧审阅。
3. 用文件工具应用必要变化，保留未涉及内容。快照局部更新，账本按状态协议追加；事件标识在当前运行内唯一，重试前核对是否已经写入。
4. 写后重新读取改动部分，逐项核对本次提交是否实际落盘、目标编号是否正确、是否漏写或意外改动。客观快照与账本的语义一致性由世界侧确认，私人变化由角色侧确认；机械核对不授予运行器额外判断权。
5. 清单全部完成并通过核对，才返回“保存完成”。无变化可以返回无需写入，不强迫三份文件每次都改变。清单和核对结果为临时执行信息，不另建持久状态。

正式运行的世界结果保存完成后才能交付相应观察，人物结果保存完成后才能继续依赖该变化的调用；每个对外暂停点前确认截至该点的必要保存均已完成。具体调用位置由 Skill 安排。

唯一建档例外：尚未建立正式运行时，两个主体可在各自权限内用初始草案及分主体起点信息校准建档；这不是正式运行中的观察投递，不推进时间、不产生正式事件，也不向用户展示未提交场景。草案全部确认并保存前不得进入首次推进。运行一旦建立，不能再以草案名义绕过上述保存要求。

## 七、恢复、中断与更正

恢复先核对编号、文件存在性和可读性；由两个主体各自检查授权状态及尚未完成的现实过程。按状态协议保存的当前事项用于续接，不把账本全文当作人物记忆，不因为旧观察仍在文件中就重新决策。

世界侧依据已保存的采用记录，检查本次处理依赖的事实来源。无需当前使用的资料不全量重载，也不因新增了其他文件就重新初始化。来源依赖按下表处理；相容性由世界核对，调用次序引用推进 Skill。

| 本次依赖的资料情况 | 恢复与使用方式 |
| --- | --- |
| 已保存的具体约束足以处理本次事项，且仍在适用范围内 | 使用本运行已采用的约束；原文件即使不可读，也不因此阻塞无须新依据的处理。 |
| 需要查阅来源，能够确认仍为已采用版本 | 读取所需部分；尚未采用的新内容仍经世界核对，不能把整份文件视为已经接纳。 |
| 来源已改版，或旧运行没有版本依据而无法确认是否相同 | 保留已成立的约束，将新读取内容作为待核对资料；不能仅凭相同文件名覆盖旧内容。原约束已过期或与新证据冲突时，由世界核查影响与合法更新来源。 |
| 来源丢失或不可读，但能找到其他适用依据 | 将替代依据交世界核对，相容且被接纳后更新来源记录，不冒充原文件已恢复。 |
| 原来源与替代依据均不足，且缺项影响本次事项 | 报告缺失的约束及受影响处理，暂停依赖它的步骤；独立的查询或资料维护仍可完成，不能跳过受影响的时序节点继续推进。 |

旧运行缺少版本标识不构成重新建档理由。能确认的既有约束继续保留，无法确认的来源部分按表处理，不倒填一个猜测的旧版本或假称已复核。永久资料版本变化本身不形成世界内事件；若资料反映制度实际生效或已经发生的外部变化，由世界区分资料接纳与现实事件，按原有时间及保存规则处理。

文件工具失败或部分写入时停止后续交接与时间推进，读取实际落盘情况，核对当次提交和已有证据。可以确认的缺漏按原提交补齐；已写入事件不重复追加，不能确认的部分保留并报告，不重新裁决出另一结果。

跨文件写入不假定为原子操作。当前上下文已丢失、无法确认最后完成位置时，报告缺失依据及受影响文件；不得宣称全部保存成功、默认重新初始化或静默覆盖历史。重新生成局部观察必须经世界侧核对现实渠道与实际可得时间，不能用恢复之名补授未知信息。

模拟外确认的记录错误或作废场景，保留原始证据和更正依据，标明哪些内容不再有效；作废条目不得继续支持当前事实。现实中新发生的纠正仍作为新事件记录。客观资料和记录错误的内容核查由世界对象第十三节负责，接入次序引用推进 Skill 第二节；涉及其他主体或需要重算历史且无足够依据时停止并报告，不借机械修复取得内容决定权。反馈保存方法引用测试规范。

## 八、引用与修订纪律

所有引用以项目根目录为基准。事项在唯一权威文件定义，其他文件使用明确路径及章节引用；调用步骤可以简短提醒约束，不能复制完整定义并独立修改。

修订时先改权威正文，再检查直接引用方、章节指向和旧路径。对象中的内部判断顺序与 Skill 中的跨主体顺序分别维护。文件整理后检查目标存在及运行内容未被误改；按第二节核对待共享文件未带入具体本地资料，并检查 Git 实际跟踪范围。流程分支的静态审核方法引用测试规范第五节；静态检查不等同于模拟行为测试。

实际测试所需的版本和证据记在对应反馈文件；有可恢复的版本引用时使用引用，无版本系统时可在该反馈的证据附录保留本次所用规范快照，并标明快照仅用于复核。没有实际测试时不创建版本存档或反馈占位文件。
