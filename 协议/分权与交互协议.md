# 分权与交互协议

## 一、权威范围

本协议唯一规定主体决定权、调用用途、临时交接接口、用户行动与推进授权、合法触发及输出条件。持久信息的含义和访问权限引用 `协议/状态协议.md`，文件操作引用 `协议/文件管理协议.md`。对象规定内部判断方法；推进范围的接入、时点比较及跨主体执行顺序统一在推进 Skill，不在此另写调度程序。

## 二、主体与决定权

角色智能体拥有意图权，决定人物的行动、私人计划和主观理解。它提交尝试，不认定外部成功或指定他人反应。“无新行动”、延迟、离开及关系自然停滞都是合法结果。

世界控制器拥有事实权，裁决现实结果、推进客观过程、生成分主体观察。它不决定核心人物的动机或关系认识，不使用私人内容安排事件。非核心人物只由世界侧维持必要的客观连续性。

运行器拥有编排权：按 Skill 调用、传递授权信息、执行文件写回、判断本协议的返回条件。它不创造动机、改写台词、裁决事实或反复要求改选。信息隔离在第一阶段是逻辑边界，同一底层模型也不能混用不同主体的知识。

真人用户决定自己的行动，是外部行动来源，不新增一个由系统模拟的用户智能体。用户可以主动联系、前往某处、等待、忽略消息或离开，不必先收到人物的交互。用户可以以接触人物为目的行动，但不能指定相遇、对方反应或关系结果；系统不得把“不制造互动”解释为限制真人动机。

用户行动助手拥有建议权，只为用户生成或修改行动与安排候选，不拟聊天回复、不代选、不裁决、不推进时间。它按需调用，没有独立生活或持续运行任务；用户手动输入与确认后的候选走同一裁决路径，不以菜单限制真人行动。

初始化由角色与世界两个对象在各自范围内建档，不是人物在世界内选择身世；助手不参与建档，也不增加第三个持续决策主体。新增一级智能体须有真实测试证明必要并经过正式架构修订。

## 三、调用用途与接口

每次调用明确目标主体、用途、当前模拟时间、本次合法材料及调用依据。以下用途只是同一对象的不同入口，不是新的智能体或持久状态。

| 主体与用途 | 允许的处理 | 返回内容 |
| --- | --- | --- |
| 角色：建档 | 形成或局部校准初始人物 | 私人人物内容、必要客观外部背景、建档检查结果 |
| 角色：查询 | 提取已有内容或核对本侧保存，不产生新决定 | 下一唤起时间；是否有已就绪而未决定的事项；已决定且待落实的外显意图（如有）；必要核对结果 |
| 角色：吸收观察 | 接收合法信息、更新当前状态及必要记忆，不提出新外显行动 | 私有更新；由当前事项导出的最小调度信息 |
| 角色：决策 | 处理新观察、到点计划或合法延续的未决事项 | 行动意图或无新行动、私有更新、最小调度信息 |
| 世界：建档 | 建立客观边界或核对外部背景与社会位置 | 初始客观内容、必要环境约束、分主体起点信息及检查结果 |
| 世界：查询 | 核对当前事实、外部过程、动作耗时与阶段条件，或核对本侧保存 | 当前合法观察、客观候选时点和依据、阶段及用户控制条件、依据是否对用户可知、必要核对结果；预测不是事实 |
| 世界：裁决与推进 | 核对用户明确提交的行动安排，裁决外显行动或落实客观过程 | 实际时间、事实、必要世界更新与事件追加、分主体观察 |
| 世界：资料核对 | 接纳模拟外客观资料或核查明确指出的记录错误，不推进时间 | 接纳或冲突结果、必要客观修订及依据；不生成世界内言语或自动投递观察 |
| 助手：行动与安排建议 | 依据本次合法材料生成或局部修订待选方案 | 候选及必要前提、需核对的缺项或无需辅助的说明；不返回已执行结果或状态更新 |

观察至少明确接收者、内容、实际可得时间与渠道。它只表达该主体实际可获得的信息，不附后台心理、关系解释或行动建议。

助手调用只传状态协议允许的用户侧材料，并明确待安排时段、未定部分与本次是生成还是修订。所缺现实条件由运行器向世界查询，并只交付经确认对用户可知的部分；不借可行性筛选泄露隐藏人物位置。助手结果是模拟外建议，不能作为观察投递或要求世界配合实现。

行动意图至少明确行动者、拟实施行为和时间；对象、渠道、外显内容及必要前提按需给出。前提仍需世界核对，意图不携带完整私人记忆或动机。

角色结果分开交接：外显意图交世界侧；私有更新供运行器机械保存；最小调度信息只供运行器排序，不外泄待处理事项正文。已决定但未落实的意图可由角色查询重新提取，不等于再次决策；若出现第四节规定的新合法触发，可由角色核查是否影响原选择，不因单纯暂停而重选。未来私人计划到点与一个已就绪、只待世界落实的意图不是同一处理阶段。建档时必要客观外部背景可交世界核对，完整私人结果仍不交世界。

每次世界裁决由运行器提供本次允许处理的时间上限与外部行动范围。世界可因现实变化提前返回，不能越过上限。上限不附人物私人计划正文或原因；人物下一唤起时间只用于内部排序，不能作为向用户展示的日程或跳时建议。

世界结果按接收者分发。无新事实、无触发点、无法确定有限范围和尚未获得推进授权是不同结果，不能混为一谈。交接默认临时存在；持久归属按状态协议处理，不传内部逐步推理。

## 四、触发、反馈与恢复

合法变化来自已有日程、承诺、制度节点、进行中过程、既有事件的后果、人物已有计划、既有处境中的外部行为或用户新行动。人物计划到点只赋予重新决定的机会，不保证执行。

角色决策可由新观察、计划到点或暂停前确已成立但尚未决定的现实事项触发。只吸收过观察不等于已经决定；已决定无新行动则是已处理，不能再次标为待处理以要求改选。恢复依据人物自己的当前状态，不重放整段历史冒充新观察。

查询不触发行动、不写入新安排。重复观察、旧话题、联系间隔、沉默、用户无聊或展示需要都不能独立构成新触发。裁决尚未执行的既有意图与重新要求角色选择必须区分。

正式运行的事实先由世界确认，按文件管理协议完成必要写回，再交付观察；人物变化另行保存。建档草案校准的适用例外只以文件管理协议第六节为准。

出现须立即交还用户的现实节点时，只完成截至该点的必要保存与观察吸收，不再启动新角色决策或推进未来时间。未决事项与待落实选择依状态协议保留。耗时行动也受同一时序约束，不能跳过更早触发；具体排序只按推进 Skill 执行。

## 五、用户输入与信息传播

### 1. 输入分类与传播

先理解整条输入，再区分其中各部分，不强制用户使用固定标签。只有歧义会实质改变行动、知情范围或时间且上下文无法判定时，才作最小澄清。

用户输入分为三组，共十一类（4＋3＋4）；同一条消息可以组合多类输入。“修改或取消安排”与“纠正错误输入或记录”分别计为一类，不合并。

- 世界内行动与安排（4类）：即时言语或动作；从当前开始的一段安排；未来某段时间的安排；修改或取消既有安排。
- 当前信息与推进（3类）：询问当前可知情况；无新要求地“继续”；指定时间、活动或条件的推进请求。
- 模拟外输入（4类）：补充客观资料；与系统讨论、请求辅助及暂停、恢复、结束或新开运行等控制；纠正错误输入或记录；调整规则或呈现方式。

明确说出口、发出的内容，经渠道裁决后才成为相应接收者的观察。陈述首先证明表达发生，不直接证明内容为真；说出口的心理描述也只证明该表达。发送、送达、读取和回复分别裁决；通知、预览、正文及群体交流均按实际渠道与接收者生成观察。

行动描述只提交用户准备尝试的行为，不自动补成搜索所有地点、长时间守候、接近或搭话等下一项选择。写给系统的猜测、考虑和私下动机不自动成为言语、世界事实或人物观察；用户不需要先证明猜测正确才能尝试行动。

询问当前可知情况只查询已有可知内容，不把后台事实授予用户。“现在我知道她在哪里吗”可以查询；“查一下她在哪里”若需要现实搜索或询问，则属于待核对的用户行动，不能作为免费查询执行。无依据时明确未知。

资料补充与记录纠错走世界“资料核对”；其他模拟外任务按根入口路由，行动建议按本节第3部分处理。真实的新安排或取消不是纠正历史错误，不能借纠错撤销不满意但合法发生的结果。暂停、结束请求停止后续执行；恢复请求仍需核对本次范围，不自动获得无限授权。

混合输入先识别整条消息中的限制、取消和前提，再处理影响行动的资料问题及安排变更，最后才执行明确要求的行动或推进；不能先执行第一句再处理后面的“但先别走”。未解决的冲突影响该行动时不先推进。纯查询、纯建议、纯模拟外任务及只登记或修改未来安排，不因旧授权尚存就自动推进。

### 2. 行动范围与时间授权

开始行动或回复，授权其现实所需的过程及当前交互的正常后续，不等于授权系统替用户跨越任意生活阶段。进行中聊天遵守真实感知、思考、动作及传输耗时，不为每句话额外询问；人物无新行动也不自动证明交流已经结束。

未来安排说明“到时打算做什么”，本身不授权现在略过中间时间。接纳课表、一周行程或修改某天安排后，先在当前时点登记；只有本次还明确要求推进，或满足下述既有范围续接条件，才进入时间推进。无需为了接受资料而要求用户先选择助手菜单。

本次明确要求执行的有限活动、推进到的时刻或已获授权安排的剩余部分，可以支持跨阶段推进。这里只授权处理范围，不保证范围内有互动，也不允许替用户作出新的重要选择。“直到她回复”之类不保证发生的结果不能作为无限终点；须另有可确认的有限上限。

范围内出现中途交互，输出后暂停实际执行，但不自动撤销原有有限安排与授权。用户作出实际回复或行动、当前交互自然结束后，可以继续原范围未执行部分；先核对新输入是否已修改或取消它、现实条件是否失效、终点是否已过，以及是否出现新的必要选择。有任一限制就按当前条件返回或重定范围，不恢复失效旧计划。没有真人新输入时，即使授权仍有效也不后台执行。

当前交互或用户指定的行动阶段结束，且没有覆盖后续的有效授权时，须在当前时点交回控制。完整组合行动在其范围内连续处理，不在每个机械子动作后重复询问。

单独“继续”或“暂时不操作”只能承接清楚且有限的当前活动、可核对的既有授权剩余部分，或已经向用户展示且仍有效的单一推进范围。多个待选行动不构成一个默认范围；没有这些依据时按下节提供安排帮助，而不是默认为若干天都不主动。确有关键缺项时才作最小询问，不把“本刻不行动”扩大成长期放弃行动。

范围说明只使用用户可知的处境和安排，不靠人物隐藏计划推导对外建议；范围是处理上限，不是未来事实。用户可以收窄范围或改变尚未执行的安排，但不能在看到后续结果后向已完成的历史插入行动。恢复时无法核对临时授权或已展示范围，按状态协议重新确认，不从保存的完整课表反推整周都已获授权。

### 3. 行动助手的触发与确认

仅在用户明确请求行动或安排建议、修订建议，或者用户要求“继续”但没有可承接范围时，调用用户行动助手。已有完整手动行动、课表或行程直接按正常输入处理，不强制转成选项；单纯聊天回复、信息询问或一般系统讨论不自动触发助手。

助手按其对象方法生成候选，运行器将其作为模拟外建议展示并交回控制；候选内容、范围和手动补充入口均由对象方法提供。生成、展示、追问或修改草稿本身不推进模拟时间、不执行行动、不登记安排；复合任务中已明确授权并完成的其他部分须与建议分开报告。

用户明确选择可唯一识别的候选，或明确提交修改后的方案，才将相应行动内容作为新的用户输入，按本节第1、2部分核对语义与时间授权，再交世界裁决；不是把助手方案直接写成事实。仅问“能否改成……”或要求换一组是修订请求，不是执行确认；手动给出的新安排可以直接替代候选。

候选即使只有一项，也不默认选中。只有先前展示的是不含待选新行动的单一有限推进范围，“继续”才可以确认该范围；面前是行动候选时，“继续”“你决定”或含糊编号都不等于任选第一项。提示用户指明选择或自行填写，不反复重生相同选项。

选择时核对所指候选、当前时间和已知前提是否仍有效。原选项上下文已丢失、编号有多种指向或重要条件已经变化时，说明具体缺项或变化，请用户重新指明或确认修订，不猜测编号、不静默改内容执行，也不为恢复选项新增持久状态。

## 六、一次调用的范围与输出

一次推进从用户输入到下一次系统输出。每次保存并输出后停止实际执行，等待真人；真人回复耗时不自动等于模拟耗时。不以固定轮数、固定世界步长或必须产生互动定义一次调用。

### 返回条件

直接送达用户的定向消息或行为、需其选择的现场变化、影响其当前承诺和可用行动的情况，均形成现实节点。沉默、离开或失败也可形成可观察节点。普通环境变化或单纯动作回显不必单独暂停，但不能因此忽略第五节规定的行动阶段结束与用户选择。

初始化完成而用户尚未提交行动或推进请求时，首次输出呈现起点可知处境并交回控制，不先跳时寻找第一次相遇。若已有明确行动或推进请求，则按同一推进入口处理；已有建议请求则接入助手分支，候选与起点观察分开显示。

到授权范围终点仍无现实节点，也须返回；原范围失效时确认当前后果后返回，不为等待互动追逐新终点。纯时间上限到达时，可处理该时点已到达的事项，但不能越界完成后续动作；更早已成立的用户控制节点始终优先。

无下一合法触发、无法确定范围、缺少授权、必要资料不足和执行失败分别说明。没有授权继续不是“世界没有事件”，一次没有遇见人物也不是模拟失败。

### 输出内容

每次模拟输出让用户能辨认当前日期、时间与必要处境；同一场景可用简短时间，跨时段明确起止或经过时长。精度与现实依据相符，不制造秒级假精度。时间和状态说明属于模拟外呈现，不混入人物台词。

现实节点输出用户合法观察；阶段结束或到界无互动时说明推进到哪里及本段可观察结果。未看见人物只能报告在实际观察范围内未见到，不能报告其隐藏位置或断言整个世界没有相关活动。

需要下一段授权且已有行动安排依据时，可附一句有限范围与提前返回条件，不必固定询问“你接下来怎么做”。仍需选择做什么时，不用一个看似纯跳时的范围夹带新行动；按第五节的触发规则决定是否给助手候选。范围由推进 Skill 组织查询，不以待确认范围先行推进。

输出不泄露私人内容、不预告未来联系，不把范围说明或“无事发生”写入事件账本。保存失败只报告实际完成情况，不显示依赖未提交结果的后续内容。

## 七、问题归属

世界问题交世界侧，人物判断交角色侧，候选内容问题交助手，保存问题按文件管理协议核查。运行器只协调，不因技术上能看到内容而获得决定权。无法由当前权威解决的关键冲突报告设计者，不通过补剧情、重新抽样或静默改写消除。
