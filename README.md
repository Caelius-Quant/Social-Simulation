# Social-Simulation

## 这是什么

这是一个通过文字交互进行的长期社会交往模拟。系统维持一个连续的世界和一名有自己生活的人物，你决定自己的言语、行动和安排，与对方的关系由实际经历自然形成。

它不以恋爱、亲密或持续聊天为目标，也没有好感度和固定剧情。对方可以主动联系你，也可以忙于自己的事情、不回复、产生误解或逐渐疏远。你可以尝试创造见面机会，但不能直接指定“我们恰好相遇”或对方的反应。

当前是基于 Markdown 文件的早期版本，需要能读写项目文件的 AI Agent 执行，没有独立程序或游戏界面。核心规范已做静态审核，尚未完成真实试跑；世界事实资料也仍待补充。

## 怎么玩

### 开始一次模拟

把整个项目下载或克隆到本地，用能读写本地文件的 AI Agent 打开这个文件夹，然后告诉它：

> 请从 AGENTS.md 开始读取项目规则，并开始一次新模拟。我的性别是【填写】，模拟对象的性别是【填写】。

不需要先读完所有内部文件。系统默认先接收双方性别，遇到影响初始化的必要缺项才会询问；完成建档后，会给出当前模拟时间和你能知道的起点处境，随后由你输入。

如果所用工具不能读写本地文件，就不能按本项目的方式实际保存和恢复模拟。只把 README 粘贴进聊天，也不等于加载了整套项目。

### 自己安排，或用“继续＋选择”参与

你可以在开始前或过程中补充自己的信息，例如专业、工作背景、所在环境、课表、某天安排，甚至整周行程。只提供你愿意用于模拟的资料，不必准备完整个人档案。系统不知道的部分不会自动当作你的真实习惯；告诉系统一件事，也不意味着对方已经知道。

想自己安排时，直接输入即可，例如：

> 这是我本周的课表。今天下课后我准备去图书馆，自习到17:00。

不想每次编写行程时，也可以采用“继续 → 必要时选择一个安排 → 继续”的方式：

- 已有清楚、有效的活动或推进范围时，“继续”会承接它。
- 缺少下一段安排时，系统会根据你已知的处境提供行动选项；如果连生成选项的必要信息都不足，会先问最少的问题。
- 你可以回复“选第二项”，也可以明确改成自己的安排，或完全手动输入。仅询问“第二项能否改成半小时”不会直接执行。
- 面前已有待选行动时，单说“继续”不会替你任选一项。选项只辅助行动与安排，不代写聊天回复。

两种方式可以随时切换。提供一周行程只是在登记安排，不表示系统会立刻跳过一周；你仍可以在之后调整尚未执行的部分。

### 每次交互会发生什么

你既可以回复对方，也可以主动发消息、前往某处、等待、离开，或先向系统询问当前情况。用自然语言描述即可，不必使用固定命令。

每次输入后，系统处理到下一次需要向你输出的位置，并说明当前时间。聊天可能只经过思考和回复所需的短暂时间；较长的安排可能推进几个小时或更久。出现更早需要你回应或选择的情况时，会提前停下；到达约定终点仍没有互动，也会说明结果，不会一直等到“有剧情”。

系统输出后等待你，不在后台继续演进。你现实中隔几天再回复，不等于模拟中也过去了几天。若一段已授权安排被中途交互打断，处理完你的实际回复后，可以在安排仍有效时继续剩余部分；单纯询问系统或登记未来安排不会自动推进。

可以说“暂停模拟”或“结束这次模拟”。以后在同一项目文件夹中告诉 Agent“请从 AGENTS.md 开始，恢复运行001”（编号换成自己的），由它核对已保存资料。各次模拟保存在 `资产/运行资产/`，默认不随 Git 提交，需要自行备份；恢复时缺失的选择或临时授权可能需要重新确认。

## 十一类输入指南

输入按协议分为三组，共十一类（4＋3＋4）：第1—4类是世界内行动与安排，第5—7类是当前信息与推进，第8—11类是模拟外输入。下面的例子不是固定指令格式，其中的身份、地点和时间应换成自己的情况。同一条消息可以组合多类输入。

| 类别 | 可以输入什么 | 例子 |
| --- | --- | --- |
| 1. 即时对话或动作 | 现在说什么、发什么、做什么；可以回复，也可以主动发起 | “我回复她：‘好，那下课再说。’”“我收起书，离开教室。” |
| 2. 紧接当前的一段安排 | 从现在开始要做的一段活动 | “我现在去图书馆，到了以后自习到17:00。” |
| 3. 未来某段时间的安排 | 登记之后某个时段的计划，不立即跳到那时 | “明天下午14:00到16:00，我准备去图书馆自习。” |
| 4. 修改或取消既有安排 | 现在改变尚未执行的计划，不撤销已经发生的行为 | “取消明天下午去图书馆的安排。” |
| 5. 询问当前可知情况 | 查询当前时间、处境以及自己已经能知道的信息 | “现在几点？我目前已经有她的联系方式吗？” |
| 6. 无额外要求地推进 | 承接现有范围；没有范围时获得安排帮助 | “继续。” |
| 7. 带要求地推进 | 指定时间、活动或提前返回条件 | “我在这里自习到17:00；中途有需要我回应的情况就先停下。” |
| 8. 补充自己的信息 | 提供尚未说明的客观背景、课表或行程资料 | “补充一下，我是金融专业。这是我本周的课表。” |
| 9. 与系统对话或控制运行 | 请求安排建议、讨论模拟问题，或暂停、恢复、结束、新开模拟 | “给我几个接下来可以做的安排。”“先暂停，我想讨论刚才的情况。” |
| 10. 纠正错误输入或记录 | 指出此前实际输错、记错的内容，请系统核查纠正 | “刚才时间输错了，是周三14:00，不是周二。” |
| 11. 调整规则或呈现方式 | 在模拟外提出规则修订，或调整输出的展示方式 | “以后每次输出都显示日期和时间。”“我想讨论并修改这条运行规则，先别推进。” |

第4类是现在改变安排，第10类是核查此前的错误，两者分开处理。不能因为不满意结果，就借修改安排或纠错把已经合法发生的经历撤销。规则修订也不会自动重写旧历史。

询问当前情况不是读取对方的内心或隐藏行程。若信息需要实际搜索、打听或发送消息才能得到，应把它作为行动提出，由系统处理所需时间和结果。

组合输入例如：

> 补充一下，我明天上午有课。取消明天下午去图书馆的安排。现在我先留在这里整理资料半小时，中途有需要我回应的情况就停下。

这条消息同时包含补充信息、修改安排、当前安排和推进条件。系统会先核对整条输入及其限制，不会只执行前半句。只是问问题、请求建议或登记未来安排时，时间不因此前进。

如果一句话容易混淆是在对谁说，可以补上“我对她说……”或“这是给系统的补充，不是在对她说”。这些标签不是必填。

本页只介绍使用方式。Agent 的入口是 [AGENTS.md](AGENTS.md)；输入的具体处理以[分权与交互协议第五节](协议/分权与交互协议.md#五用户输入与信息传播)为准。
